## 3. Derivation rules (deterministic)

The postimages were generated by the included `author_repairs.py`, byte-exact
from index preimages (`git show :path`), applying four rules:

* **R1 (doc rows).** Each of the 36 wrapper rows' canonical cell is replaced
  by the wrapper's actual import tuple in file order — the same tuple the
  gate reports. Migration-table rows are untouched.
* **R2 (facade expansion).** Every flagged historical import is replaced by
  its recursive canonical expansion (facade→facade chains expanded until no
  historical name remains), deduplicated, keeping only members not already
  covered by the file's transitive closure. Coverage is computed to fixpoint
  against the **final** (post-repair) import graph, so no repair leans on a
  facade edge that another repair removes.
* **R3 (aggregate hygiene).** The three aggregates are re-emitted
  casefold-sorted unique, per the layout gate's `unsorted_aggregate_imports`
  and duplicate-import rules.
* **R4 (layering trim).** The `Higham21` facade expansion would have pushed
  17 `NumStability.Source.*` imports into the `NumStability.Algorithms`
  umbrella, breaching its `NumStability.Source. <= 49` direct-import ceiling
  (49 pre-existing + 17 = 66 > 49). Because the umbrella is import-only and
  every other module still reaches that content, the Source-prefixed
  additions are dropped from the umbrella instead. See reviewer decision D1.

## 7. Reviewer decisions (non-mechanical, need human sign-off)

* **D1 — Algorithms umbrella layering (chosen: trim).** Variant A (chosen):
  drop the Source-prefixed expansion members from `NumStability/Algorithms.lean`,
  keeping the `NumStability.Source. <= 49` ceiling intact; the umbrella's own
  reach shrinks by the 10 enumerated `Chapter21` modules, all still reachable
  by every consumer. Variant B (alternative): keep the expansion and amend
  the ceiling 49 → 66 in `layout-exceptions.json` (28th path). Variant A
  preserves the ceiling's design intent (containing Source-reach leakage the
  retired `Higham21` facade had introduced); Variant B preserves the
  umbrella's exact closure. The generator emits Variant A; Variant B is a
  one-line change to `author_repairs.py` (skip Pass 2b).
* **D2 — Source-tree canonical homes.** `Higham21RankStability` and
  `Higham21QRFoundations` forward into `Source.Higham.Chapter21.*` (not
  `LinearSystems/Underdetermined`), so several `Algorithms.LinearSystems.*`
  repair files gain direct `Source.*` imports. No layout rule forbids this
  (only the umbrella has ceilings), and the pattern pre-exists, but it is a
  layering choice worth an explicit nod.
* **D3 — facade→facade exemption.** The gate exempts historical modules from
  the production-import rule, so `RealQuasiSchur` (facade) importing
  `RealInvariantSubspace` (facade) is unflagged (see
  `05_compatibility-errors.log` for what *was* flagged). This repair leaves
  that as is; confirm the exemption is intended policy.
* **D4 — W04 retained-closure files.** Errors 45–52 flag five files that are
  themselves W04 facades/retained-closure modules living *inside* the
  canonical `LinearSystems/Underdetermined` tree:
  `MinimumNorm/Solvers/Executor/Core.lean`, `Perturbation/Bounds/Core.lean`,
  `QR/Givens/Rounded/Core.lean`, `QR/ModifiedGramSchmidt/Rounded/Core.lean`,
  and `SeminormalEquations/EndToEnd/Core.lean` (the last carries four flagged
  imports). They are treated as production here, exactly as the gate treats
  them. Confirm.
* **D5 — request-record conventions.** `R0008.json` mirrors `R0006.json`
  field-for-field (`lane_id`, `blocks`, `depends_on` drafted by analogy).
  Honest caveat: the shadow's `02_completion_full` PASS was obtained
  **without** R0008 registered in the phase docs, so it says nothing about
  whether the drafted record will satisfy the completion checker once the
  milestone-DAG / branch-record / narrative registrations are added; those
  registrations are integrator-side work at acceptance, and the drafted JSON
  is a starting artifact, not a gate-validated one.
* **D6 — union supersession protocol.** See §2: recommended immutable-record
  + chain-of-custody treatment vs re-cut union artifact.
